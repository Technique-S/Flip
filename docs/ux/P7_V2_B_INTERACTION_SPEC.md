Retain Flip's white/gray workbench, blue `#0055cc` selection/focus, current type scale, compact borders, NAND shape, REF cards, layout, viewport and adjacent inspector. Do not add a visual theme, new animation system or second graph engine. The current implementation, not the historical architecture's illustrative `wires` array, is the visual and semantic baseline.

## Pointer flow and feedback

1. Inspect a source pin or begin dragging its output handle. Label source as “External input [0], width 1” or “nand0 output [0], width 1”; source aliases and processor/decimal circuit ID stay inspectable. Do not invent names such as carry/sum unless the actual component ID supplies them; user IDs do not establish semantic intent.
2. Keep accepted wires solid. Draw a distinct dashed preview from the selected source to the pointer. A preview is labeled “Connection preview — not applied”; its existence is not structural acceptance. Hovering any destination runs synchronous local eligibility checks only.
3. An eligible target receives outline + “Can propose replacement — validation required.” An invalid one receives a reason in text and `aria-describedby`, plus a distinct outline/icon. Do not reuse equivalence verdict colors or display a green success check. Hover and keyboard focus show the same reason. Avoid per-move live announcements.
4. Drop on an eligible destination opens a nonmodal inspector Review with **destination, previous source → proposed source, zero-based pins, width 1, and canonical slot locator**. The old wire remains solid; proposed replacement is dashed. Do not dim the old line enough to make it unreadable. Show “Apply connection” and “Cancel”; focus Review heading then make Apply the next action. Target is locked for that review; picking another source explicitly replaces/discards the proposal.
5. Apply sends one existing compose POST for the full proposal. Status: “Validating nand0 output [0] → carry input [1]. Accepted wiring remains in use.” Prevent duplicate submissions. Keep graph and Advanced table on accepted wiring during pending validation. Keep Cancel reachable outside disabled fieldsets, including after opening Review from the canvas.
6. Success regenerates the accepted projection and highlights the target wire, with a concise announcement: “Connection updated at revision N. Compare again for this revision.” Focus the originating pin/action if still present; otherwise its inspector heading. Do not steal focus from a user who moved elsewhere during validation.
7. Failure preserves accepted wiring, history, dirty checkpoint and both source choices. Show native error/code plus “Connection not applied. Previous source remains …”. Offer Retry and Cancel, not a default fallback source. Retry must check current base again and make one new request. Resource failure uses the dedicated capacity wording in the F1 plan; it never becomes EQUIVALENT.

Invalid target reasons have a stable priority: editor/project unavailable → unsupported kind/state/identity → wrong direction → missing pin → range/width → self/forward ordering → resource profile. Examples: “Start from an output pin”; “Final outputs are destinations”; “carry must appear before nand0 to feed this input. Component reordering is unavailable”; “Source output [2] does not exist; this REF exposes [0]”; “Stateful REF wiring is unsupported.” On empty drop say “No destination chosen; wiring unchanged.” No automatic node creation, nearest-target commit or silent pin-index correction.

Escape cancels from drag, click/tap selection, Review or pending validation; do not consume Escape from an open native select before the select closes. Background click clears a picking preview, not an accepted edge. Pointer cancellation, multi-touch interruption, navigation/unmount and project replacement invalidate the gesture token. Do not allow a late `onConnect` callback to resurrect a cancelled preview. Drop-to-review requires both endpoints and the captured base to still exist.

## Existing wire inspection

Click/focus an edge or activate its exact-mappings row to show identical endpoint text, locator and selected target. Highlight just that wire and endpoints with stroke/outline + text, without changing mappings or proof. An output's fan-out inspection can list all destinations and highlight them locally; each replacement still selects one destination. Escape exits inspection. “Change source” opens an explicit source picker with its destination fixed; this gives a straightforward replacement flow without draggable edge endpoints. Edge selection is not connection-level diagnosis and must not add Canary claims, relevant-path overlays or simulated signal values.

## Keyboard, touch and assistive technology

Provide a complete native-control path: Inspect component → Inspect pin → Use as source → Destination kind/component → Destination input/output index → Review → Apply connection. Alternatively inspect a destination and choose Change source. Native selects enumerate only eligible sources while a nearby text help panel explains excluded categories/order. No drag, exact coordinate, held modifier or global shortcut is required. Tab order follows inspector reading order; Enter/Space activates buttons; no global Ctrl/Cmd-Z interception interferes with text editing. Normal Undo/Redo buttons reverse one accepted connection each.

Touch supports source tap then target tap and the same Review, plus the fixed-size inspector controls. Keep blank-space pan and pinch zoom; one active gesture only, no hidden long-press requirement. Do not claim touch acceptance from mouse tests or emulation alone. Test actual touch hardware when available and report the device, browser and observations. Until then hardware acceptance is NOT TESTED.

Use `role=status`/polite atomic announcements for source selected, review opened, validation started, committed, cancelled and already connected. Announce an invalid target only on explicit activation or changed focused reason; no hover flood. Submitted errors are associated with Review controls and announced once; avoid duplicated React Flow and editor live messages. Pin controls retain explicit direction/index/width; a node with interactive descendants remains a group, not a nested button. Screen readers need a usable table/picker without traversing every spatial handle. Preserve visible focus and ensure focused inspector/target is not obscured.

Pointer targets must measure at least 24×24 CSS pixels with adequate spacing, with a preferred 44px control/hit region for touch. At zoomed-out graph scales, provide the equivalent fixed-size inspector control on the same page; do not claim an 8px dot or transformed 44px world-space box meets viewport target sizing. Prevent overlapping hit regions from selecting adjacent pins. Prefer inspector picking on dense/narrow graphs, with a clear focus route back to the canvas. At 390px and 200% browser zoom, keep Review/buttons readable and the document free of horizontal overflow; the exact table may scroll within its own container. No flashing/pulsing preview, no required animation; respect reduced-motion settings.

## React Flow adapter decisions and research

Keep locked `@xyflow/react` **13.0.2**. Its installed source exposes `onConnect`, start/end and click-connect callbacks, strict connection mode, `connectOnClick`, and handle start/end flags; confirm each against that pinned package during implementation. Official documentation was inspected on 2026-11-26; it is supporting API research, not a replacement for the lockfile or a claim that future behavior already works.

- Use controlled nodes/edges generated from accepted Execution; no `defaultEdges`, `addEdge`, `reconnectEdge`, edge-store serialization or “apply edge changes” path may mutate accepted circuit authority. `onConnect` translates a gesture into a proposal and opens Review. `onConnectEnd` cleans invalid/empty/cancelled gestures, never commits. Supply explicit strict mode; source handles start only, destination handles end only. Global eligibility callback shares the pure command precheck. [React Flow component reference](https://reactflow.dev/api-reference/react-flow), [Handle reference](https://reactflow.dev/api-reference/components/handle).
- Disable endpoint reconnect handles and deletion in the first V2-B release; occupied-target replacement is sufficient. Source/destination inspection and native pickers share one translator/command. Choose one click/tap state owner: the application picker. Disable library `connectOnClick` initially and route explicit pin-button source/target selections through that picker, avoiding two overlapping click sessions. Drag uses the library callbacks; both paths share the same application generation token. This is a design choice, not a missing library capability.
- React Flow's example adds edges into component state after its predicate; Flip must instead stage canonical binding review. A local predicate is only an eligibility preview. [Validation example](https://reactflow.dev/examples/interaction/validation).
- Its focus and ARIA support is a foundation; built-in node/edge selection is not a complete numeric-pin keyboard wiring workflow. Retain custom native controls and replace default descriptions that promise deletion/movement. Test focus visibility, avoid duplicate live regions and keep graph wrappers semantically correct. [React Flow accessibility](https://reactflow.dev/learn/advanced-use/accessibility).
- WCAG 2.2 requires a single-pointer alternative to dragging and addresses minimum target size. Native picking supplies that alternative and keyboard support; actual conformance still requires testing. [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [W3C dragging guidance](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements), [G219](https://www.w3.org/WAI/WCAG22/Techniques/general/G219.html).

Proposed performance gates, not measurements: build indexed component/port eligibility once per accepted revision; no network/native work on pointer move; O(1) target eligibility from indexes; no full-request clone, history mutation or React tree-wide edge allocation per frame. Target local eligibility/feedback under 50ms and smooth pointer preview on the supported reference machine; measure p95 and long tasks at small, typical and largest allowed profiles before acceptance. Keep existing 500-component / 1,000-edge / 4,096-visible-pin projection ceilings, request/table/history budgets, and native resource controls. Do not raise limits to make a demo pass. Native validation has its own typed failure/limits; do not invent a new UI timeout that converts pending work into success.
